# CrewForge5

Claude Code plugin under `plugin/` (the installable package; the marketplace installs it as a `git-subdir`). The repo root holds tests, CI, `docs/` and dev tooling, none of which ships. Dogfood output (runs of this plugin on this repo: `crewforge5/`, `.crewforge5/`, `.team-sprint/`, plans, newly generated crews and agents) is committed only on the local `dogfood` branch, which holds the generated `bash` crew (`.claude/crews/`, `.claude/agents/`, `.claude/rules/bash.md`); `main` stays package-only (spec R-H8). `.gitignore` ignores that output and `scripts/tests/repo_hygiene.bats` fails if any of it is tracked here. The stages, config hygiene, the crew factory and the execute shortcut are slash commands (`/crewforge5:init`, `/crewforge5:crew`, `/crewforge5:plan`, `/crewforge5:design`, `/crewforge5:build`, `/crewforge5:review`, `/crewforge5:execute`, in `plugin/commands/`) over the Python verdict CLI. There is no flow skill and no flow driver (spec phase 8); every skill is hidden know-how a command names by path, and `team-sprint` survives only as the graph-mode Teams path behind `/crewforge5:execute --teams` until a real sprint is measured both ways (decision D3). The alignment with cc_sdlc (Python verdict CLI, slash commands, human-accepted artifacts) is specified in `docs/specs/cc-sdlc-alignment.md`; its §6 order is the roadmap, and its §7 decisions are final.

## Commands
- Test: `just test` (every bats suite, then `uv run --group dev pytest`; all green, never skip or delete a failing test). While iterating, run `bats <file>` directly: `run-all.sh` re-runs the whole team-sprint suite inside `lint_skill.sh`.
- Lint: `just lint` (`shellcheck` over every `.sh` under `scripts/`, `plugin/scripts/` and `plugin/skills/`, which must be clean under shellcheck 0.9, the version Ubuntu CI installs; `ruff check .` and `ruff format --check .` over all the Python, plugin included).
- Pre-commit: `just precommit` (the `.pre-commit-config.yaml` hooks CI runs); `just hooks` installs them.
- Release gates: `just gates` (`plugin/scripts/{budget_check,name_check,validate_all}.sh`, `scripts/verify_degradation.sh`, `claude plugin validate --strict plugin` and `--strict .`).
- Everything: `just check`. Run it before reporting a task complete and paste the tail. If a test fails, fix the code, not the test.
- Try locally: `just opus` (or `just fable`) runs `claude --plugin-dir plugin`; then `/crewforge5:plan new "<title>"`. Dogfood on the `dogfood` branch, never on `main`.
- Versions: never bump by hand. The CI `version` job runs `scripts/bump_version.py` on each same-repo PR (label `major|minor|patch`, default patch), bumping `plugin/.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `pyproject.toml` and `uv.lock` together and dating `## Unreleased` in the CHANGELOG.
- No `just`? Each recipe is a plain command in `justfile`; CI runs the same ones.

## Architecture
- Paths below are under `plugin/` unless they start with `.github/`, `docs/`, `tests/` or root `scripts/{tests,verify_*,bump_version.py}`.
- `commands/{init,crew,plan,design,build,review,execute}.md` are the commands: frontmatter (`description`, `argument-hint`, least-privilege `allowed-tools`), then `templates/command-preamble.md` verbatim, then `new/check/accept/status` sections (review: `run/review/evals/status`; crew: `survey/forge/validate/status`); at most 40 lines (`tests/test_commands.py`). Each stage and init runs one read-only `workflows/<name>.js` (`crewforge5:config-audit|intent-scout|design-panel|plan-critic|review`) with an inline fallback (review's is the `reviewer` agent); `build implement` also runs `crewforge5:story-executor`, which writes only inside per-step git worktrees and returns branches the command applies around `build red|green`. `commands/execute.md` on an accepted `crewforge5/<slug>/plan.md` is the shortcut for `build implement`, then `review run` and `review review`, then the self-improve distillation (R-S7); `--teams` runs `skills/team-sprint/` on the story plan `scripts/plan_stories.sh` builds from the accepted plan.md.
- `skills/` holds 13 hidden skills (`disable-model-invocation: true`, none listed): know-how the commands and agents read by path, plus `team-sprint`, the Teams path (phase docs under `references/phases/`, ~30 scripts under `scripts/`, its own bats suite and `lint_skill.sh`; its sprint state is `.team-sprint/sprints/`, the one run directory outside the feature home). Retired skills' surviving content is in `templates/` (`interview.md`, `concerns.md`, `adversarial-stamp.md`, `house-rules.md`, `repomix-flags.md`).
- `scripts/crewforge5/` is the Python 3.11 stdlib verdict CLI (spec D1), launched as `uv run --no-project "${CLAUDE_PLUGIN_ROOT}/scripts/crewforge5.py" <stage> <action> [arg] [--slug s]`; it prints one JSON verdict `{ok, reason, next, ...}`. `project.py` (config, home, `fail`), `artifacts.py` (template sections and `Status:`/`Risk:`), `stages.py` (`plan|design|build new/check/accept` over `intent.md`/`spec.md`/`plan.md`, and `status`), `checkpoint.py` (the commit after each accept), `build.py` (`build accept|sync|fix`, the accepted-plan gate, `build-state.json`), `tdd.py` (`build red|green`, `tdd.jsonl`, `complete()`/`require()`), `review.py` (`review run|review`: `test-report.json`, `review.md` validation; `review review` is a checkpoint boundary), `init.py` (`init new|check|accept|status`: measures a config root through the skills' gate scripts via `project.script`, `<home>/init-<date>/audit.md` + `measure.json`; `init accept` is a checkpoint boundary), `crew.py` (`crew survey|validate|status` over `.claude/crews/<lang>.json`, and `require()`, the `[build] require_crew` gate in `build accept`), `evals.py` (`review evals`, `claude -p` via `CREWFORGE5_CLAUDE_BIN`), `workflows.py` (`workflows list|env`: catalog from each script's JSON `meta`, the `[workflows.env]` merge), `knowledge.py` (`knowledge bootstrap [check]|status|refresh|check`: the Graphify graph and the OKF bundle, cc_sdlc's `sdlc/knowledge/` when present, else `<home>/knowledge/`), `packs.py` (`knowledge pack <stage>`: commit-pinned Repomix packs under `graphify-out/packs/`, and `require`, the `build accept` / `review review` gate), `docs.py` (`docs render|check|open <stage>`: Archify stage documents under `<slug>/docs/`; `check` gates `plan|design|build accept` and `review review`), `hooks.py` (session-start, pre-edit, post-edit; launched by `scripts/hook.py`), `migrate.py` (`migrate [<source>]`: moves a 0.x `.crewforge5/<flow>/<subject>/` run or `docs/plans/*.md` plan into `<home>/<slug>/migrated/` once), `cli.py` (dispatch). `templates/` holds the artifact skeletons and the default `crewforge5.toml`. Every command calls it.
- `agents/` are the plugin agents (`reviewer` opus and `verifier` sonnet are read-only; `crew-factory`, `stack-surveyor`); each carries the R-G6 never-work-around-a-hook line and declares no `hooks`/`permissionMode` (`repo_hygiene.bats`). `hooks/hooks.json` wires the Python hooks (`scripts/hook.py session-start|pre-edit|post-edit`, through `uv run --no-project`) and the bash ones (`bash-guard`, `learn-capture`, `learn-nudge`, the root announcement). Every hook acts only in a project with `.crewforge5.toml` and stops under `[hooks] enabled = false` (bash hooks source `hooks/hooks-on.sh`); `CREWFORGE5_HOOKS=1` is retired. Timeouts ≤10 s except session start.
- Tests: root `scripts/tests/*.bats` (gates, docs surface, hooks, repo hygiene; `ROOT` is `plugin/`, `REPO` the checkout), `plugin/skills/*/scripts/tests/` and `plugin/skills/*/tests/` (per-skill, still inside the package until they are ported), and root `tests/` (pytest for the verdict CLI and `scripts/bump_version.py`; `conftest.py` has the in-process `run` fixture and the `accepted_*` walk). Every bats suite sources the one root `scripts/tests/lib/bats-fallback.sh`. `docs/adr/` holds ADRs; `docs/specs/` holds specs.

## Conventions
- stdout is a machine contract (`KEY=VALUE`, one `STATUS=` line); human text goes to stderr. Exit codes: 0 ok, 1 error, 2 usage.
- Every new `.bats` file sources the root `scripts/tests/lib/bats-fallback.sh` by a path relative to its own directory (five `../` from `plugin/skills/<s>/scripts/tests/`), and its directory is named in `.github/workflows/ci.yml` (`repo_hygiene.bats` enforces both).
- Every agent in `plugin/agents/` declares `name`, `description`, `tools` and `model` (`repo_hygiene.bats`).
- Locate the plugin from the script's own path (`$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd -P)`), or `${CLAUDE_PLUGIN_ROOT}` in skill text the harness expands. Never fall back to `.`: it is the user's repo, not the plugin (`repo_hygiene.bats` fails on the old fallback).
- Verdict CLI: config comes only from `project.config()` (defaults from `templates/crewforge5.toml` deep-merged with `.crewforge5.toml`). Expected failures raise `project.fail(reason, **extra)`; success returns a dict with `ok: true` and `next`. A new layer with an off switch joins `project.LAYERS` and the plugin README's off-switch table (a test checks both).
- Python tests drive the CLI in-process through the `run` fixture, never a subprocess of `crewforge5.py`. They run with `CREWFORGE5_CHECKPOINT=off` unless they take `checkpoint_on`, listed before any `accepted_*` fixture, and with `CREWFORGE5_KNOWLEDGE|PACKS|DOCS=off` unless they take the `knowledge`, `packs` or `docs_tools` fixture, which put fake `uv`/`graphify`, `repomix`/`npm`/`bandit` and `node`/`npx` on a sandbox PATH; never let a test reach the real tools.
- Commit messages: Conventional Commits, `<type>(<scope>): ...`.
- CHANGELOG: newest release on top, entries under `## Unreleased` (the CI bump turns it into `## X.Y.Z — date`), about 15 lines per release. Longer rationale goes in the PR or an ADR. Never rewrite past entries; they record what was true then.
- The always-loaded context (skill, agent and command `description`s) is a release gate with ~80 tok of headroom; `budget_check.sh` also pins that no skill is listed and the commands (`init`, `crew`, `plan`, `design`, `build`, `review`, `execute`, `rules-install`). Lengthening a description can fail `budget_check.sh`, and so can moving the numbers `docs_surface.bats` checks in the README and CHANGELOG.

## Things Claude gets wrong
- Shell state does not survive a tool call. An `export` dies with its own Bash command, so nothing may rely on a variable a previous call set. Carry values in files or state, not in the shell.
- Hooks do not inherit session exports. They are spawned by the harness; only `settings.json`'s `env` block reaches them.
- `${CLAUDE_PLUGIN_ROOT}` is expanded in hook commands and in skill/command text the harness loads. It is not in the Bash tool's environment, and it is not expanded in files read later with Read (phase docs).
- CI runs macOS too: bash 3.2 (no `mapfile`, no `declare -A`, no `${x^^}`), BSD `sed -i ''`, and `stat -f` means *filesystem* on GNU. Try `stat -c` first.
- A literal `@test` at column 0 inside a heredoc registers a phantom test under Ubuntu's older bats. Build nested fixtures with `printf`.
- An unquoted YAML `description:` containing `: ` silently drops the whole frontmatter. Quote it.
- Hidden skills (`disable-model-invocation: true`, i.e. all of them) cannot be reached by the `Skill` tool. Name them by path (`${CLAUDE_PLUGIN_ROOT}/skills/<name>/SKILL.md`): read an inline one, spawn a `context: fork` one through the Agent tool with the `agent:` type it declares.
- A `while` loop fed by a pipe runs in a subshell, so its failures and counters vanish. Feed it with redirection.
- Nothing the plugin needs at runtime may live outside `plugin/`: users get only that directory. Dev-only files (tests, CI, probes, `bump_version.py`) must not go inside it.
- `${CLAUDE_PLUGIN_ROOT}` is `plugin/`, not the repo root; a script's self-located root (`$HERE/..`) is `plugin/` too. Root-level dev scripts reach the package through `$REPO/plugin`.
- `cli.main(argv, root)` never prints and is the only place `Blocked` is caught (a test greps for it); `entry()` prints. Never return `{"ok": False}` by hand. Hooks reach a mechanic through `cli.main([...], root)` so they need no `except Blocked` of their own.
- A skill directory named like a command collides: Claude Code names plugin skills by directory, not by frontmatter `name`. That is why `/crewforge5:execute` could become a command only once `skills/execute/` was gone.
- The init and crew mechanics shell out to the skills' gate scripts only through `project.script(root, rel, *args)`; tests replace that one function with a stub (`tests/test_init.py`, `tests/test_crew.py`) rather than running bash and jq.
- A workflow's `export const meta` must stay strict JSON (double quotes, no trailing commas) and list every `phase('X')` / `phase: 'X'` title the body uses; `tests/test_workflows.py` parses it. No `Date.now`/`Math.random`: they break resume.
- A step is done only when `build red <n>` then `build green <n>` return `ok`; tests set `[commands] test` to `exit 1`/`exit 0` through the `toml_config` fixture rather than running a real suite. Hook tests take a `.crewforge5.toml` (hooks are inert without one).
- `.gitignore` patterns for dogfood output are anchored (`/crewforge5/`): unanchored, `crewforge5/` also ignores the `plugin/scripts/crewforge5/` package.
- `review review` refuses a `test-report.json` whose `sha` is not HEAD: after committing a fix for an Important finding, run `review run` again before re-reviewing. `review.md` has no `Status:`/`Risk:` line; it is validated by `review.findings`, not `artifacts.validate`.
- A test that takes both an `accepted_*` fixture and `packs` or `docs_tools` lists `accepted_*` first (fixture order), or its accepts are refused for want of a pack or a stage document. Pack test repos keep the sandbox (`bin/`, `home/`, `claude/`) in `.git/info/exclude`, or `git add -A` commits it and the graph looks stale.
- Never render stage documents or install anything from a hook (R-G7); `knowledge bootstrap` installs only with `[knowledge] auto_install = true`, and pack verdicts name paths and rule ids, never matched text.
- This container runs as root, so bats tests that rely on read-only permissions fail locally (`findings_gate.bats` "unreadable plan", `recon_log.bats` AC11/AC11b). They pass in CI; do not "fix" them.
